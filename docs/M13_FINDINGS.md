# M13 findings — first portable multi-diphone waveform

M13 moves the Nicolai port from isolated raw diphones to a continuous waveform
built from multiple database units. No legacy x86 code is executed.

## 1. What is proven vs provisional

M12 proved that Nicolai's ANA payload is direct G.711 A-law audio at 16 kHz.
M10 proved deterministic phone-pair -> AXM -> SEG -> ANA lookup.

M13 observes that, after the first four SEG control words, voiced diphones contain
positive values in the ~150–220 sample range. At 16 kHz this corresponds to
roughly 73–107 Hz, physically plausible pitch periods for the recorded male
voice. Fully voiced records such as `m->a0`, `a0->a0`, `a0->m` contain clean
runs of these values.

The complete SEG control language is NOT yet proven. Negative values and mixed
voiced/unvoiced records are therefore not assigned speculative meanings. M13
uses only positive values in a conservative speech-scale interval (40..400) as
*pitch hints* for boundary alignment.

## 2. Portable join added

New module:

```
include/nicolai/psola_join.hpp
src/psola_join.cpp
```

Pipeline:

```
phone chain
  -> exact database diphones (M10)
  -> G.711 A-law -> PCM16 (M12)
  -> pitch-hint extraction from SEG
  -> bounded phase search around the shared phone midpoint
  -> complementary half-Hann / raised-cosine overlap-add
  -> continuous PCM16 waveform
```

The join searches at most half a pitch period on each side of a boundary. This
prevents arbitrary deletion of a unit while allowing voiced phases to line up.
The overlap itself is approximately one pitch period and uses complementary
weights whose sum is exactly one.

This is a **PSOLA-like first stage**, not yet a bit-exact reproduction of the
legacy Tempo-PSOLA duration/pitch regulator.

## 6. What remains for M14

The next step should stop treating SEG periods merely as hints and recover the
legacy TDS/Tempo-PSOLA control semantics:

1. map the first four SEG words and negative control tokens;
2. reconstruct explicit pitch-mark positions for voiced and mixed units;
3. recover the legacy Hanning-window table/selection behavior;
4. use pitch-synchronous grains rather than one boundary crossfade;
5. compare M14 output against a reference WAV generated by original SpeechCube
   for the same manually supplied phone sequence, if such a reference is made
   available.

After that, the remaining major layer is the Russian text/prosody frontend:
UTF-8 text -> phoneme/accent/duration sequence -> the already-working acoustic
backend.
